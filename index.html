Git

Snapshots: status, stage, commitGuide + practice

Git records project snapshots. Your working folder holds edits; staging chooses what goes into the next commit. Review the diff before committing. Run these commands inside an existing repository.

shell
git status
git diff
git add index.html styles.css
git diff --staged
git commit -m "Improve notes layout"
git log --oneline -5

Common mistakes

git add . can include secrets and unrelated files. Commits stay local until pushed. Write messages that explain the change.

Try it yourself

Change a heading in a practice repository. Stage only that file and inspect the staged diff.

Show practice answer

Use git add with the exact filename, then git diff --staged. Confirm only your heading edit is present before committing.

Branches, merge, and safe undoGuide + practice

A branch names a line of commits. Use feature branches to work independently. Replace main with your actual default branch; this website uses master. Revert creates a new undo commit for shared history.

shell
git switch -c feature/notes
# Edit, stage, and commit first.
git switch main
git merge feature/notes
# Inspect a commit before undoing it:
git show COMMIT_ID
git revert COMMIT_ID

Common mistakes

git reset --hard discards tracked local edits. git restore FILE discards unstaged edits; git restore --staged FILE only unstages. Rebase rewrites history: avoid rebasing shared commits. Use --force-with-lease rather than --force only when rewriting your own branch is intentional.

Try it yourself

Unstage a file in a disposable practice repository without deleting your edits.

Show practice answer

git restore --staged filename unstages it; git status shows modified content still present in your working folder.

Terminal commands

Navigate with PowerShellGuide + practice

A terminal runs commands in a current directory. These are PowerShell examples, matching this project. Quote paths containing spaces and inspect paths before modifying them.

powershell
Get-Location
Get-ChildItem
Set-Location -LiteralPath "C:\Projects\my website"
Get-Content -LiteralPath "index.html" -TotalCount 10
New-Item -ItemType Directory -Path "practice"

Common mistakes

PowerShell, Bash, and cmd have different syntax. Bash export NAME=value is not PowerShell syntax. Check targets before pasting deletion commands.

Try it yourself

Create a practice directory, enter it, and display your location.

Show practice answer

New-Item -ItemType Directory -Path practice; then Set-Location practice and Get-Location. Set-Location .. goes back.

Pipelines, environment, exit codesGuide + practice

PowerShell pipelines pass objects between commands. Environment variables configure the current process and child processes. Native commands report success or failure through $LASTEXITCODE.

powershell
Get-ChildItem -File | Sort-Object Length -Descending | Select-Object -First 5 Name, Length
$env:PORT = "3000"
node --check script.js
if ($LASTEXITCODE -ne 0) { throw "Syntax check failed" }

Common mistakes

Do not print secrets or commit .env files. A later successful command can mask an earlier failure unless you check it. PowerShell object pipelines differ from Bash text pipelines.

Show practice answer

HTML describes meaning. Use a descriptive page h1, a main landmark, and real buttons for actions. Every input needs an associated label. Browser validation helps users; the server must still validate submitted data.

html

Modern CSS

Responsive Grid and FlexboxGuide + practice

Grid arranges rows and columns; Flexbox distributes items along one main axis. Start with narrow screens. minmax(0, 1fr) and min-width: 0 let long content shrink instead of pushing the page sideways.

css
:root { --space: 1rem; --accent: #facc15; }
.cards { display: grid; gap: var(--space); grid-template-columns: 1fr; }
.card { min-width: 0; overflow-wrap: anywhere; }
.toolbar { display: flex; flex-wrap: wrap; gap: .75rem; }
@media (min-width: 48rem) {
  .cards { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}

Common mistakes

Fixed widths and absolute positioning are fragile for page layout. overflow-x: hidden may hide the problem and content. Test long words and browser zoom.

Try it yourself

Show practice answer

Cascade, containers, and motionGuide + practice

The cascade considers origin, layers, specificity, and order. Scope component styles instead of relying on !important. Container queries respond to a parent container. Respect reduced-motion preferences and visible keyboard focus.

css
.notes-shell { container-type: inline-size; }
.note-card { padding: 1rem; }
@container (min-width: 40rem) { .note-card { padding: 1.5rem; } }
button:focus-visible { outline: 3px solid #93c5fd; outline-offset: 3px; }
@media (prefers-reduced-motion: reduce) {
  .note-card { animation: none; transition: none; }
}

Common mistakes

A container cannot use its own size query to restyle itself: target descendants. Never remove focus outlines without a replacement. Test contrast over photos.

Try it yourself

Show practice answer

Set .note-card { transition: border-color .15s ease; }, add a hover border color, and keep the reduced-motion transition: none rule.

JavaScript

Values, functions, arraysGuide + practice

Use const for bindings you do not reassign and let for bindings you do. const does not freeze objects. Functions return results. map transforms arrays; filter keeps matches.

javascript
const tasks = [{ id: 1, done: false }, { id: 2, done: true }];
const pending = tasks.filter(task => !task.done);
const completed = tasks.map(task =>
  task.id === 1 ? { ...task, done: true } : task
);
console.log(pending.length); // 1
console.log(tasks[0].done); // false

Common mistakes

Use === for comparison without coercion. map needs a return value. Copying an array alone does not copy nested objects.

Try it yourself

Double every number without changing the input array.

Show practice answer

const doubleAll = numbers => numbers.map(number => number * 2); doubleAll([1, 2, 3]) returns [2, 4, 6].

DOM events, promises, errorsGuide + practice

Find elements after the DOM exists, register listeners, and update text safely. Async functions return promises; await pauses that function until a promise settles. Catch failures and restore loading state in finally.

javascript
const button = document.querySelector("#load-button");
const status = document.querySelector("#load-status");
button.addEventListener("click", async () => {
  button.disabled = true;
  try {
    const response = await fetch("/api/notes");
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const notes = await response.json();
    status.textContent = `Loaded ${notes.length} notes`;
  } catch { status.textContent = "Could not load notes. Try again."; }
  finally { button.disabled = false; }
});

Common mistakes

Requires matching button/status elements and an endpoint returning an array. Do not put untrusted input in innerHTML. Syntax success does not mean the network will succeed.

Try it yourself

Add a loading message before the request.

Show practice answer

Set status.textContent = "Loading notes…" after disabling the button. Keep finally so the button recovers from both success and failure.

React

Components, props, stateGuide + practice

Components return UI. Props are read-only inputs from a parent; state is memory that triggers renders. Use functional updates when the next value depends on the old value. JSX requires a configured React project.

jsx
import { useState } from "react";
export default function Counter({ initial = 0 }) {
  const [count, setCount] = useState(initial);
  return (
    <button onClick={() => setCount(previous => previous + 1)}>
      Count: {count}
    </button>
  );
}

Common mistakes

Do not mutate state arrays with push; use setItems(previous => [...previous, newItem]). Use stable data IDs as list keys. Never call Hooks conditionally or in loops.

Try it yourself

Add a Reset button returning the counter to initial.

Show practice answer

Wrap both buttons in a fragment and add <button onClick={() => setCount(initial)}>Reset</button>.

Effects and cleanupGuide + practice

Effects synchronize an external system, such as a timer or subscription. Calculate derived values during rendering instead of storing them in duplicate state. Effects need cleanup. Strict Mode may run an extra setup/cleanup cycle during development.

jsx
import { useEffect, useState } from "react";
export default function Clock() {
  const [now, setNow] = useState(() => new Date());
  useEffect(() => {
    const timer = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(timer);
  }, []);
  return <time dateTime={now.toISOString()}>{now.toLocaleTimeString()}</time>;
}

Common mistakes

An Effect callback must not be async: it must return cleanup or nothing, not a promise. Include reactive dependencies. Prefer framework data-loading facilities when available; manual requests need cancellation and stale-response handling.

Try it yourself

Explain the consequence of removing timer cleanup.

Show practice answer

The interval can continue running after unmount, wasting work. The cleanup stops it.

APIs

HTTP methods, status codes, JSONGuide + practice

An API defines a contract between programs. GET reads; POST commonly creates; PUT replaces; PATCH partially updates; DELETE removes. JSON represents data. fetch does not reject only because the server returns 404 or 500: check response.ok.

javascript
async function getNotes() {
  const response = await fetch("/api/notes", {
    headers: { Accept: "application/json" }
  });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}
// Call inside an async function:
// const notes = await getNotes();

Common mistakes

Do not parse 204 No Content as JSON. 401 means authentication is needed; 403 means access is denied. CORS is not authentication. The example requires an API endpoint.

Try it yourself

Describe loading, empty, and failure states.

Show practice answer

Show progress while loading, a helpful empty state for [], and a retryable error after failure. Restore disabled controls in finally.

Parameters, cancellation, paginationGuide + practice

URLSearchParams encodes query values. AbortController cancels slow or obsolete requests. Paginate large collections. Abort older searches and check response versions so stale results cannot replace new ones.

javascript
async function searchNotes(query) {
  const controller = new AbortController();
  const timeout = setTimeout(() => controller.abort(), 8000);
  try {
    const params = new URLSearchParams({ q: query, limit: "20" });
    const response = await fetch(`/api/notes?${params}`, { signal: controller.signal });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } finally { clearTimeout(timeout); }
}

Common mistakes

Do not join raw user values into URLs. Handle AbortError separately for expected cancellation. Retrying non-idempotent requests blindly can create duplicates.

Try it yourself

Show practice answer

A small HTTP JSON serverGuide + practice

A server receives requests and sends responses. Check routes and methods; use explicit status codes and content types. This development example binds to loopback, making it accessible only on your computer.

javascript
import { createServer } from "node:http";
const server = createServer((request, response) => {
  const url = new URL(request.url, "http://localhost");
  if (request.method === "GET" && url.pathname === "/api/health") {
    response.writeHead(200, { "Content-Type": "application/json; charset=utf-8" });
    response.end(JSON.stringify({ ok: true }));
    return;
  }
  response.writeHead(404, { "Content-Type": "application/json" });
  response.end(JSON.stringify({ error: "Not found" }));
});
server.listen(3000, "127.0.0.1");

Common mistakes

Save as server.mjs and run node server.mjs. Production needs input validation, body-size limits, timeouts, logging, appropriate authentication, and HTTPS. Never expose arbitrary filesystem paths as routes.

SQL

Tables, joins, aggregationGuide + practice

SQL queries relational tables. Primary keys identify rows; foreign keys link tables. WHERE filters rows; GROUP BY aggregates; ORDER BY makes ordering explicit. This schema uses integer IDs supplied by the application.

sql
CREATE TABLE topics (id INTEGER PRIMARY KEY, name VARCHAR(100) NOT NULL);
CREATE TABLE notes (id INTEGER PRIMARY KEY, topic_id INTEGER REFERENCES topics(id), title VARCHAR(200) NOT NULL);
INSERT INTO topics (id, name) VALUES (1, 'Git');
INSERT INTO notes (id, topic_id, title) VALUES (1, 1, 'Branches');
SELECT topics.name, COUNT(notes.id) AS note_count
FROM topics LEFT JOIN notes ON notes.topic_id = topics.id
GROUP BY topics.id, topics.name
ORDER BY topics.name;

Common mistakes

Use IS NULL, not = NULL. LEFT JOIN keeps topics without notes; COUNT(notes.id) returns zero for them. SQL dialects differ in generated IDs and pagination.

Try it yourself

Show practice answer

SELECT id, title FROM notes WHERE title LIKE '%Git%' ORDER BY title; Case sensitivity depends on database and collation.

Parameters, indexes, transactionsGuide + practice

Bind user values as query parameters, not SQL text. Transactions make related changes succeed or fail together. Indexes can speed lookups but cost storage and work on writes. This JavaScript example uses PostgreSQL pg and a previously connected client.

javascript
const result = await client.query(
  "SELECT id, title FROM notes WHERE topic_id = $1 ORDER BY id LIMIT $2",
  [topicId, 20]
);
await client.query("BEGIN");
try {
  await client.query("UPDATE notes SET title = $1 WHERE id = $2", [title, noteId]);
  await client.query("COMMIT");
} catch (error) {
  await client.query("ROLLBACK");
  throw error;
}

Common mistakes

Use the same connection throughout a transaction. Parameters bind values, not identifiers; allowlist dynamic table names. Check WHERE before UPDATE or DELETE.

Algorithms

Big O and binary searchGuide + practice

Big O describes how resource use grows with input size. Linear scans are O(n). Binary search halves a range each step: O(log n) time, but it requires sorted input. This iterative version uses O(1) auxiliary space.

javascript
function binarySearch(sorted, target) {
  let low = 0, high = sorted.length - 1;
  while (low <= high) {
    const middle = low + Math.floor((high - low) / 2);
    if (sorted[middle] === target) return middle;
    if (sorted[middle] < target) low = middle + 1;
    else high = middle - 1;
  }
  return -1;
}
console.log(binarySearch([2, 4, 7, 9], 7)); // 2

Common mistakes

Unsorted input produces incorrect results. low = middle can cause an infinite loop; advance to middle + 1. Sorting first costs time, so binary search is not automatically best for one lookup.

Try it yourself

Test empty input, missing targets, and first/last items.

Show practice answer

Expect -1 for [] and a missing target; expect 0 for 2 and 3 for 9 in [2, 4, 7, 9].

Sets, maps, problem solvingGuide + practice

Sets store unique values; Maps associate keys with values. Begin with a correct simple solution, identify repeated work, then choose a data structure. Explain time and space costs and test boundaries.

javascript
function countWords(text) {
  const counts = new Map();
  const words = text.toLowerCase().match(/[a-z]+/g) ?? [];
  for (const word of words) counts.set(word, (counts.get(word) ?? 0) + 1);
  return counts;
}
console.log(countWords("Git git CSS").get("git")); // 2
const unique = [...new Set([1, 1, 2, 3])]; // [1, 2, 3]

Common mistakes

The regex handles English ASCII words, not all languages. Maps compare object keys by identity. Lookup is efficient in typical implementations; do not promise constant-time guarantees for every engine.

Try it yourself

Show practice answer

Testing

Node unit testsGuide + practice

Unit tests check behavior with controlled inputs. Test boundaries and failures, not only success. The built-in Node runner needs no extra framework. Save this as sum.test.mjs and run node --test.

javascript
import test from "node:test";
import assert from "node:assert/strict";
function sum(values) { return values.reduce((total, value) => total + value, 0); }
test("sums positive and negative values", () => {
  assert.equal(sum([3, -2, 4]), 5);
});
test("empty input returns zero", () => {
  assert.equal(sum([]), 0);
});

Common mistakes

Passing tests prove only the checked behaviors. Avoid copying implementation logic into tests. Control time, storage, and networks to keep tests deterministic.

Try it yourself

Show practice answer

assert.equal(sum([7]), 7); assert.equal(sum([0, 0]), 0); use descriptive test names.

Security

Untrusted text and script injectionGuide + practice

Treat user input and third-party API fields as untrusted. Insert text with textContent rather than innerHTML. Intentional rich HTML needs a maintained sanitizer with a restrictive policy. Content Security Policy adds protection but does not replace safe rendering.

javascript
const name = '<img src=x onerror="alert(1)">';
const output = document.createElement("p");
output.textContent = name;
document.querySelector("#results").append(output);
// Markup is displayed as text, not executed.

Common mistakes

A few regex replacements are not an HTML sanitizer. Validate URL protocols. Client validation does not replace server validation and authorization.

Try it yourself

Render a title containing <script> as plain text.

Show practice answer

Create an element, assign title to textContent, and append it. Never pass the title to an HTML parser.

Authentication, permissions, secretsGuide + practice

Authentication identifies users; authorization checks what they may do. Enforce both on the server for each protected resource. Keep secrets out of browser bundles and Git. Passwords require vetted password-hashing libraries, such as Argon2id implementations, not plain SHA hashing or reversible encryption.

javascript
// Connected PostgreSQL client on the server:
async function loadOwnedNote(client, authenticatedUserId, noteId) {
  const result = await client.query(
    "SELECT id, title FROM notes WHERE id = $1 AND owner_id = $2",
    [noteId, authenticatedUserId]
  );
  return result.rows[0] ?? null;
}
// authenticatedUserId comes from a verified server session.

Common mistakes

Assumes notes has owner_id. Never trust browser-supplied user IDs as identity proof. Restrict public API keys by origin/API; they remain visible. Use HTTPS and secure session cookies; cookie-authenticated mutations also need CSRF protection.

Try it yourself

Why does hiding an Edit button not secure an endpoint?

Show practice answer

Users can call the endpoint directly. The server must verify the session and check permissions before every read or update.

Current guidance for the original notes

  • Use the actual default branch (master in this repository); new projects may use main. A branch name is not a filename.
